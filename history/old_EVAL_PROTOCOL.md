# 检索评测协议（含"图关系扩展"对照实验）

> 目的：用数据裁决三件事——
> (1) 现有双通道检索的**入口质量**（日志行 → 正确案例）；
> (2) 附加**一跳关系扩展**（"图"）是否提高分析上下文的价值，代价多大；
> (3) **安全边界**：负样本（新案例）是否会被错误扩展，是否产生误导性关联。
>
> 原则：离线评测；**先定判据、后跑数据**；查询用机械变换生成（防按检索键定制）；小样本只报观察级结论（沿用 PAT 惯例）。

---

## 1. 评测问题与预判假设

| 编号 | 问题 | 先写下的假设（跑完可推翻） |
|---|---|---|
| P1 | 入口召回：给定日志行，能否召回正确案例 | 原样行可达性高（但含写键时的"看题"成分）；泛化能力只看变异行 |
| P2 | 扩展效用：正确案例的一跳邻居是否值得随附 | 同技术簇（mitre 词面通道已覆盖）的扩展**大概率冗余**；增量价值与风险集中在**跨手法/跨阶段边**（chain_sibling、shares_infra） |
| P3 | 安全边界 | 扩展在"新案例"路径上零触发；不产生 misleading 关联 |
| P4（可选） | 批次回放：结论层面是否有变化 | 定性记录，不作主要证据 |

## 2. 评测集构造

### 2.1 三类查询（分开统计，不混算）

**Q-A 原样历史行**（可达性检验）
- 来源：`data/test_prev_batches.txt` 全部 7 行 + 此后每批留档行（建议把每批 `data/incoming_logs.txt` 归档到 `eval/batches/`）。
- 注意：这些行在编写 `retrieval_keys` / `pattern_probes` 时可能已被"看过"→ 分数乐观，**只能证明"可达"，不能作为泛化证据**。

**Q-B 机械变异行**（泛化能力的主力证据）
- 用脚本对种子行做**确定性变换**（带随机种子、可复现），变换清单：
  1. 基础设施轮换：DGA 域名 → 保持形状的新随机域名（`8hex.6char.net`）；解析 IP → 同段新 IP；主机名换编号（`app-rails-38` → `app-rails-71`）
  2. 编码变换：URL 单编码 / 双编码 / 大小写混合 / `%uXXXX`；载荷段 base64
  3. 分隔符扰动：`;` ↔ `%3b`、空格数量、`&&` ↔ `%26%26`
  4. 大小写与字段顺序扰动；追加无关字段（UA、referer 变体）
  5. 自然语言改写：一行日志 → 一句中文/英文描述（**预期词面掉分**，用于测量语义盲区大小）
  6. 边界样本：同时沾两个案例的行（如 T1190 + 横向关键字）
- 每条标注：目标案例、变换类型、**不变性声明**（"必须仍命中" / "可降级"）。
- 规模：每案例 3–5 条 × 9 案例 ≈ 30–45 条。

**Q-C 负样本（新案例行）**
- 库中不存在的类目（如钓鱼邮件、勒索加密、挖矿流量），可构造 5–10 条。
- 期望：返回空或弱分噪声 → 【新案例】；**扩展零触发**。

总量参考：50–80 条。小样本一律报原始计数 + 比例 + 典型例子。

### 2.2 查询标注（qrels）

```json
{"qid": "Q-B-013", "source": "variant", "text": "……",
 "must": ["CASE-002"],
 "helpful": ["CASE-004"],
 "misleading": [],
 "expect": {"min_tier": "强", "expansion_ok": true},
 "variant_of": "CASE-002", "transform": "dga_rename", "invariance": "必须仍命中"}
```

- `must`：入口必须召回的案例（负样本为空）。
- `helpful`：作为分析上下文**能改变/增强结论**的关联案例（链邻接、同类不同画像、基建复用）。
- `misleading`：表面相似但实质不同，引用会误导判断的案例（防确认偏差）——单列统计，一票否决制。
- 标注人：你 + Agent 均可初判，但**必须写明理由**；关键条目进盲评复核（§6）。

### 2.3 关系 Gold 矩阵（扩展评测的主 Ground Truth）

- 范围：9 案例全部两两 = 36 对，**全量手工裁定**（当前规模完全可做）。
- 每对输出：

```json
{"pair": ["CASE-003", "CASE-005"],
 "related": "helpful",
 "types": ["same_technique", "same_family"],
 "evidence": "同 T1190；同 WAF/RASP 双层命中形态",
 "direction_note": "005→003 有帮助；003→005 较弱"}
```

- `related` 等级：`must` / `helpful` / `weak` / `unrelated` / `misleading`。
- 关系类型词汇：`shares_infra` / `same_technique` / `same_family` / `shares_payload` / `same_phase` / `chain_sibling`（以 `relations_gold.json` 的 meta 为准）。
- **顺序纪律**：先手工裁定矩阵，后实现任何自动推导规则。反序会自我循环。
- 重点裁定对象：跨簇边（web 簇 → 横向簇）。它决定"扩展会不会把无关案例拉进来"。
- 初扫发现（供裁定参考）：T1190 簇 {003,005,006,008,009}、T1033 簇 {001,004}；当前字段级推导的 shares_infra 命中为空（indicators 里混有描述性备注，见 §7）。

## 3. 对照配置（消融矩阵）

同一查询集 + 同一 qrels，跑以下配置：

| 配置 | 通道 | 扩展 | 目的 |
|---|---|---|---|
| C0 | keys only | 无 | 通道基线 |
| C1 | keys+mitre+ind+signature | 无 | 全词面 |
| C2 | C1 + probes | 无 | **现状（当前 src/retrieve.py）** |
| C3 | C2 | 一跳扩展·全部关系类型 | 处理组（"图"） |
| C4 | C2 | 一跳扩展·跨簇/跨阶段类边（shares_infra / chain_sibling / same_phase） | 关系类型消融 |
| C5 | C2 | 一跳扩展·簇内/同技术类边（same_technique / same_family / shares_payload） | 关系类型消融（验证"簇内冗余"假设） |

**触发门槛子实验**（在 C3/C4 选定后跑）：
- 门槛甲：种子 score ≥6（强）才扩展
- 门槛乙：≥4（中）即扩展
- 产出："什么分数下允许扩展"的操作规则。

预留：向量通道上马后加 C6 = C2+向量、C7 = C3+向量（评测集直接复用）。

## 4. 指标定义

### 4.1 入口指标（每配置 × 每类查询）

| 指标 | 公式/口径 |
|---|---|
| Hit@1 / Hit@3 | must ∩ top-k(返回集) ≠ ∅ |
| Recall | \|must ∩ 返回集\| / \|must\| |
| MRR | 首个正确案例排名的倒数 |
| 强档精度 | must 查询中正确案例 score≥6 的占比（阈值校准用） |
| 误召回量 | 每查询返回的 non-must/non-helpful 案例数（均值） |
| **misleading 命中次数** | 单列，最重要（期望 0） |
| 负样本空返回率 | Q-C 中返回空的比例（期望 ≈100%） |

### 4.2 扩展指标（仅对"入口命中"的 Q-A/Q-B 查询计算）

设 B_q = C2 返回集，E_q = C3 返回集（= B_q ∪ 邻居），H_q = 该查询 helpful 集。

| 指标 | 公式/口径 | 含义 |
|---|---|---|
| CR B→E | 基线→扩展后 helpful 召回（差值=扩展增益；gold 直连阶段 CR(E) 为上界） |
| 扩展精度 EP | \|(E_q\B_q) ∩ (H_q∪must)\| / \|E_q\B_q\| | **只看扩展新增部分**的精度 |
| 新发现数 | Σ 查询：helpful ∩ (E_q\B_q) | 正贡献（基线漏、扩展补） |
| 噪声数 | 扩展新增中 weak/unrelated 个数 | 负贡献（misleading 单列重罚） |
| 候选成本 | 平均返回数 B̄ → Ē | 分析者负担 |
| 零扩展率（负样本） | Q-C 中未触发扩展的比例 | 门控有效性 |

### 4.3 判读规则（预注册——跑之前定死，不许事后改口）

建议初始阈值（可整体上调/下调，但须在跑数据前敲定）：

1. **新发现 : 噪声 ≥ 2:1** 且 噪声 ≤ 0.5 条/查询；
2. **misleading 关联 = 0 次**；
3. 负样本零扩展率 ≥ 90%；
4. 若噪声超标 → 收窄关系类型（看 C4/C5 谁稳）或升高触发门槛；
5. **若新发现 ≈ 0 → 结论就是"不需要扩展"**（分析期人工翻库已够）——这是一个合法的实验结论，不是失败。

## 5. 产物与执行顺序

```
eval/
  batches/            # 每批 data/incoming_logs.txt 的归档（从本批起）
  seed_queries.jsonl  # Q-A 种子（原样行 + 构造行）
  gen_variants.py     # 机械变异生成器（确定性、固定随机种子）
  queries.jsonl       # 查询 + 标注（由 seed+gold 机械派生）
  relations_gold.json # 全矩阵裁定（当前 22 案例 / 231 对）
  run_eval.py         # 跑 C0–C5 → results/report.md
  run_recall_full.py  # 全数据集重放召回审计 → results/report_recall_full.md
  results/
```

执行顺序：
1. **先裁定** relations_gold.json（当前 22 案例 / 231 对，review 清单见报告附录B）与 Q-A/Q-C 的 qrels；
2. 跑 `gen_variants.py` 生成 Q-B → 补标注；
3. `run_eval.py` 一次跑全部配置，输出指标表 + 逐查询对照；
4. 盲评复核关键条目（§6.2）→ 出结论；
5. 判决后才动 `src/retrieve.py` 主流程（改动走原有"历史行回归"纪律）。

**隔离原则**：评测全程不改动现行 检索→判断→提取 流程；`run_eval.py` 只读 queries/gold，不写 data/memory_store.json。

## 6. 防偏差与陷阱清单

1. **循环论证**：变异查询由脚本机械生成，生成器不看 `retrieval_keys`；gold 关系手工先于推导规则。
2. **评测者偏差**：盲评轮——打乱配置输出、隐藏通道来源，只问"该案例对该查询是否有用"（三级：有用/无关/误导）；揭盲后再对照。
3. **训练/测试污染**：Q-A 只作可达性证据；泛化结论仅取自 Q-B/Q-C。新增案例后，此前批次的行可转 Q-A，但不得把"入库后重跑命中"当泛化证据。
4. **小样本**：report 给计数与比例 + 例子，不追 p 值；结论标"观察级"。
5. **对照公平**：所有配置共用同一查询集、同一评分实现；C3–C5 的关系先验一律来自 gold 矩阵（而非运行中的自动推导），确保测的是"扩展这个动作"的效用。
6. **回归复用**：本评测集同时充当 src/retrieve.py 改动的回归套件，替代/补充目前手工回归（validation_notes.md 的重放幂等测试保留为额外健全性检查）。

## 7. 与后续阶段的衔接

- **扩展被采纳后**再实现自动推导：`shares_infra` = 精确 IOC 交集、`same_technique` = mitre 交集、`chain_adjacent` = kill_chain 邻接；用 gold 矩阵比 precision/recall，决定"全自动 / 推导+人工确认 / 维持手写关系"。
- **schema 微调（推导前必做）**：`indicators` 现混有描述性备注（如"waf 与 rasp 双层同时命中"、"cross_wave_ip_reuse"），与可精确匹配的 IOC 值混在一起会污染 shares_infra 推导。建议拆成 `iocs`（只放可精确匹配值）与 `notes`（自由文本）。
- **向量通道**：若后续评估，直接在 C6/C7 位置接入同一评测集；向量结果一律以 advisory 级呈现（标注"需字面确认"），入口证据仍以符号通道为准。

## 8. 效度声明与结论边界（怎么写结论）

**"数据好看"的三个结构性注水来源（引用任何结论时必须一并声明）**：
1. **回顾性重放**：召回审计与 Q-A 使用的行，多数就是写案例时的证据行——"能被召回"接近同义反复；只证可达性，不证检出能力。
2. **合成数据的高判别度**：样本为刻意设计的干净指纹（独特 token、双层告警、完整时间戳），真实流量不具备这种可判别性。
3. **自产自测**：查询、变体、负样本、gold、判据出自同一方；gold 38 条 review 尚未裁定。

**可信结论类型（按可信度排序）**：
1. **相对比较类**（最可信，混淆因素对配置共享）：probes 贡献在档位不在命中；稠密簇内边+多种子联合=噪声源，稀疏跨簇边+top-1 来源=零噪声；机械推导精度 ~20% → 候选+人工确认是可行路径。
2. **失败模式类**（最有价值产出）：组件兜底通用词泄漏；过泛探针被负样本抓到（CASE-013）；规模效应——案例 9→22 时噪声/查询 0.25→0.91（精度随规模可测退化的真实信号）；通用行交叉面；跨模板歧义（010/011）。
3. **可行性类**：机制可运行、失败可定位、成本可控（限合成数据范围）。

**不可得出的结论**：任何绝对性能数字（不可外推真实流量/新攻击）；"图能提升分析质量"（只测了上下文被捞出）；泛化至未见手法（无留出攻击集，负样本偏易）。

**补强路径（按性价比）**：
1. gold 复核（38 条）——草稿变裁定，一次性抬升全部比较类结论可信度；
2. **前瞻测试**（最干净）：新批次到达时"先检索后提取"，用事前成绩替代重放——流程天然支持，是摆脱回顾性污染的唯一路径（**已执行首轮**：data-921-930 → `results/report_recall_unseen.md`；召回端 21/21 强档、误报端 3/3 强档误报——通用 token 多通道重复计分）；
3. 独立/对抗变体 + 近邻负样本（同产品不同漏洞、良性流量）；
4. 下游效用 A/B（图问题专用：批次回放对比分析质量）。

**GRAPH_DECISION §6 落笔措辞建议**：结论限"设计约束级"（若采用图：稀疏跨簇边 + top-1 来源 + 强档门控 + 标注输出 + 人工确认边），注明"绝对性能未验证，待前瞻批次与金标复核后补强"。
