### [A-01] Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions（MemoryAgentBench）
- 轨道 / 类型: 学术 / 基准数据集论文（同行评审）
- 作者·机构: Yuanzhe Hu, Yu Wang, Julian McAuley（arXiv 页面与 OpenReview 页面均未标注机构）
- 出处: arXiv:2507.05257 (v4) · ICLR 2026 Poster（OpenReview: DT7JyQC3MR）
- 日期: v1 2025-07-07；v2 2025-09-26；v3 2026-03-17；v4 2026-06-28；OpenReview 发布 2026-01-26
- 链接: https://arxiv.org/abs/2507.05257
- 访问情况: 2026-09-28 读到 `abs` 页面全文（摘要、版本历史、comments 字段）**及 OpenReview 论坛页全文**（含 venue、TL;DR、Keywords、Primary Area、submission number）；**正文 HTML 未获取**
- 方法: 以记忆科学与认知科学的经典理论为依据，先定义 memory agent 的四项核心能力——准确检索、test-time learning、长程理解、选择性遗忘——再把已有长上下文数据集与新构造数据集改写为"增量多轮"格式，模拟记忆单元被逐步累积（而非一次性给定）的过程；随后在同一基准上评测从朴素上下文、RAG 到外部记忆模块与工具型 agent 的多类系统。
- 结果: 摘要层面结论是"当前方法无一掌握全部四项能力"；摘要未给分项数字。可核的外部数字来自后续工作：本账本 [A-15] 报告，在该基准 **v3 的 FactConsolidation 分片、262K 上下文**下，已报告的最好检索/记忆结果为 HippoRAG-v2 的 54% 单跳，BM25 48%、MemGPT 与 Cognee 28%、Mem0 18%、Zep 7%、GPT-4o 长上下文 60%；多跳变体（FC-MH）在全部 22 个已报告系统上 ≤7%。该分片由 MQUAKE 反事实改写拼接而成，反事实版本携带更大的序列号，**提示词明确写出"更新的序列号更大"**。[A-14] 报告其符号验证器把该分片单跳从 0.46–0.95 提升到 0.93–0.98。[A-19] 把它列为三个评测数据集之一。
- 意义: 它把"记忆评测"从单一问答准确率改成四项能力的口径，其中"选择性遗忘"与"test-time learning"是 LoCoMo/LongMemEval 覆盖较弱的部分；其 FactConsolidation 分片已成为 2026 年衡量"冲突更新/信新弃旧"的公共切片（且自带显式版本元数据），也是本课题"案例被新情报覆盖后能否取到当前有效版本"的现成标尺。需要注意该分片的多跳口径极低（≤7%），是"关系推理"在现有系统上的公认天花板。
- 疑点·局限: 四项能力由论文自定，非社区共识口径；基准由长上下文 QA 改造而来，与真实交互流/日志流的分布差异未被量化（正文未读，无法核）；我未读到正文，故分项得分、基线配置、评测规模都无法在此确认。**FactConsolidation 自带"序列号越大越新"的显式元数据，这使得它比真实场景容易得多**——这一点由 [A-15] 明确指出，我在报告中必须连带说明。

### [A-02] LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory
- 轨道 / 类型: 学术 / 基准数据集论文（同行评审）
- 作者·机构: Di Wu, Hongwei Wang, Wenhao Yu, Yuwei Zhang, Kai-Wei Chang, Dong Yu（arXiv 页面未标注机构）
- 出处: arXiv:2410.10813 (v2) · ICLR 2025（arXiv comments 字段标注）
- 日期: v1 2024-10-14；v2 2025-03-04
- 链接: https://arxiv.org/abs/2410.10813
- 访问情况: 2026-09-28 **读到全文 HTML**（正文 110KB 文本，已通读摘要、引言、方法（索引/检索/阅读三阶段与控制点）、实验设置与消融结论、附录中的 judge 验证与商业系统评测说明）
- 方法: 500 道人工整理的问题，每道都需要从一到多个任务型对话中回忆信息，覆盖五项能力：信息抽取、多会话推理、时序推理、**知识更新**、**拒答**（对历史中未提及的信息答"我不知道"）。受"大海捞针"启发，为每题编译一段连贯且可自由调节长度的聊天历史；提供两个标准设置：LongMemEval_S（每题约 115k token、约 50 个会话）与 LongMemEval_M（500 个会话、约 150 万 token）。方法上把长期记忆形式化为巨大的键值存储 [(k,v),...]，并拆成三阶段：索引（把每个历史会话转成一个或多个键值项）、检索（构造查询取 top-k）、阅读（LLM 读检索结果并生成回答）；据此提出三处优化——**会话分解**（value 粒度：用会话/轮次/事实而非整段）、**事实增强的键扩展**（把抽取的用户事实拼进 key）、**时间感知的索引与查询扩展**（value additionally indexed by event dates，检索时用 LLM 抽取时间范围过滤）。
- 结果: 与 oracle 检索（只给证据会话）相比，四个长上下文 LLM 在读完整个 LongMemEval_S 时出现 **30%–60% 的性能下降**，无论是否使用 chain-of-note；作者据此推断历史继续增长时还会进一步退化。商业记忆助手（ChatGPT、Coze）在**比 LongMemEval_S 简单得多**的设置下发现在 30%–70% 准确率区间（97 道随机题、3–6 个会话的历史；且因无法跨月交互而跳过部分时序题、跳过 assistant 侧记忆题、未测拒答）。消融数字：事实增强的键扩展（K = V + fact）平均提升 recall@k **9.4%**、最终准确率 **5.4%**；时间感知索引与查询扩展平均提升 recall **11.3%**（轮次为 value）与 **6.8%**（会话为 value），且该增益**依赖用强 LLM 抽取时间范围**（Llama 8B 会幻觉或漏掉时间线索）。评测用 prompt 工程的 GPT-4o judge，在 GPT-4o 与 Llama-3.1-8B 作生成模型时与人类专家判断一致度 ≥90%，仅在"单会话偏好"与"拒答"两类上略有偏差。
- 意义: 它是"知识更新"与"拒答"被写进公共评测口径的源头，而这两项正是本课题最关心的（案例失效、新旧情报冲突、无匹配案例时应拒答）。更实用的是它的三阶段分解与两条具体优化：**把抽取出的事实拼进索引键、把事件日期作为第二检索通道**——这两条与本项目"关键词×3 / MITRE 编号×2 / 指标×2 / 签名×1"的加权打分是同一类思路的学术版本，可以用来论证"确定性符号通道是有效的检索信号"而非退而求其次。
- 疑点·局限: 500 题规模小，单题波动影响大；评测依赖 LLM judge（作者自己给出 ≥90% 一致性并说明偏差类别）；商业系统评测是在**明显简化**的设置下做的，不能与 LongMemEval_S 分数并列；"30%–60% 下降"是相对 oracle 检索的设定，不是绝对准确率。300 字内最该保留的一句：**其关键增益（事实键扩展、时间通道）都发生在"索引与检索"侧，而不是"存更多"侧**。
- 采纳信号: ICLR 2025；被大量 2026 年工作当作公共刻度：[A-05] 用它做淘汰审计（470 道证据标注题），[A-06] 用它做公开对照诊断（500 题），[A-12] 报告在其 500 题上 75.2%，[A-15] 用它做二次验证，"LongMemEval-S" 已成子集专名。

### [A-03] Evaluating Very Long-Term Conversational Memory of LLM Agents（LoCoMo）
- 轨道 / 类型: 学术 / 基准数据集论文 + 预印本
- 作者·机构: Adyasha Maharana, Dong-Ho Lee, Sergey Tulyakov, Mohit Bansal, Francesco Barbieri, Yuwei Fang（arXiv 页面未标注机构；项目页 snap-research.github.io/locomo，我未打开项目页核实机构）
- 出处: arXiv:2402.17753 (v1) · 会议收录情况未在页面标注
- 日期: 2024-02-27（仅 v1）
- 链接: https://arxiv.org/abs/2402.17753
- 访问情况: 2026-09-28 **读到全文 HTML**（正文 82KB 文本，已通读摘要、生成流水线、三项任务定义、基线设置、结果与局限）
- 方法: 机器-人工混合流水线生成"超长期对话"：每个 LLM agent 被赋予 persona 与**因果互联的事件时间线**，配记忆与反思模块检索历史用于对话生成，并具备分享图像与回应图像的能力（其 agent 架构直接沿用 Generative Agents）；生成后由人工标注者修改长程不一致、删除或替换无关图像、并校验对话与事件图的接地关系，**标注者改动了近 15% 的对话轮次、删除或替换了约 19% 的图像**。由此收集 **50 段**超长期对话，每段平均 **300 轮 / 9K token / 最多 35 个会话**。评测含三项任务：问答（分单跳、多跳、时序、常识/世界知识、**对抗性**五类，对抗题期望模型判定为"无法回答"）、事件图摘要（以事件图为正确答案，要求从对话历史中抽取）、多模态对话生成。
- 结果: 长上下文 LLM 在**对抗性问题上表现比 base 模型低 83%**，且特别容易把对话或事件错配给错误的说话人；gpt-3.5-turbo-16k 的对抗题表现跌至 2.1%（Llama-2-Chat 22.1%、4K 上下文的 GPT-4-turbo 70.2%），作者据此认为长上下文下模型更易被诱导产生幻觉。事件摘要任务中，长上下文模型（gpt-3.5-turbo-16k）并未超过 base 模型，精度降 3.0%、召回降 8.7%，即"更长上下文并不等于更好利用上下文"。RAG 被作者评价为"平衡的折中"，并且**在把对话转成关于每个说话人的生活与 persona 的断言（observations）数据库时表现尤其好**；而以会话摘要为检索单元时召回偏低，作者归因于"对话转摘要过程中的信息丢失"。多模态生成中 MM-Relevance 随对话历史变长而下降，RAG 能部分缓解。
- 意义: 是"超长期对话记忆"最常被引用的基准，也是本课题"案例复用"的最接近学术形态（多会话、事件级、含时间与因果）。对本项目最有价值的两点：一是它的核心机制本身就是**persona + 因果事件图 + 断言式 observations 库**，与我们"结构化案例库 + 关系边"结构同源；二是它明确报告"以摘要为检索单元会丢信息、以断言为检索单元表现更好"，这正是"符号化案例优于摘要压缩"的一条直接证据。同时，其对抗题上的溃败提醒：没有"拒答/无法回答"这一档，长上下文模型会自信地编造。
- 疑点·局限: 对话为合成、再由人工校对（作者披露改动比例，可核查但是合成分布）；论文没有给出"落后人类"的统一量化数字（摘要只作定性表述），因此报告中不宜引用"显著落后人类"作为数值结论；仅 v1，无版本更新；评测以 F1 部分匹配为主，作者自己说明为保证可自动评测而让答案尽量取自对话原文（即答案分布被人为规范化）。产品宣传中常用的"LoCoMo 分数"（如检索中出现的 Mem0 博客 LoCoMo 92.5）与论文原始口径不可直接比较——这一不可比性是我在检索中直接观察到的现象，不是论文的主张。

- 轨道 / 类型: 学术 / 评测方法论文 + 预印本

- 意义: 它给了"预算-准确率"之外的第三种评测口径：**不可逆损失**。对本课题的意义有两层。一是"记忆单元被淘汰/覆盖"造成的损失大部分不可由更好的检索挽回（98% 并非潜伏在存量里），所以写入与保留策略比检索算法更关键。二是它明确论证"预算-准确率曲线必须连同检索机制一起报告"——这正是任何"回顾性重放 / 自产自测"式评测最容易漏掉的效度条件，也是本报告在评价本项目自建评测时应当引用的规范。
- 疑点·局限: 单作者预印本，未见同行评审；**只用了一个基准（LongMemEval-S）**、两个 reader、一个主 judge，且作者自述"审计 judge 与其提供方相同"；"不可逆"依赖 A1 假设（只在干净全 gold 注入下答对的题才被计分），因此排除弃权行为、也把结论限定在"可回答的切片"上；方法假设 gold evidence 可被识别并注入，在 open-domain 场景下不总成立；论文明确说这是"分析工具，不排名策略"，故不可用于比较淘汰策略优劣。

- 意义: 对"要不要上图库"给出的不是立场而是成本结构。对本项目的对照基准直接相关：在数十个记忆单元、查询量远低于 10^5 次/刷新的场景下，图数据库的决策变量落在 **ingest 与运维成本**而非查询延迟上——也就是说，上图的收益必须在查询侧有极大回报才能覆盖它自己的代价。它同时给出一条可复用的方法学：任何"用不用图库"的结论都应当连同查询量/刷新比一起报告。

- 结果: 在 LoCoMo 上，在**共享答案 prompt** 下于 7 个被复现系统中取得最高 strict-judge 分：**61.01 vs 最强基线 58.70**；构建与检索阶段**不需要任何生成式 LLM 调用**，作者强调"其构建成本为零，回答成本也是最低的"。锚消融（anchor ladder）显示三个锚各自贡献显著增量，且"锚点结构、而非生成"承载了准确率差距。作者另有报告：答案风格被控制后，有锚的记忆仍是更强的一方。
- 意义: 提供了一条"零生成式调用构建 + 保留原文"的路线证据：结构与线索来自机械/局部处理而非 LLM 摘要，从而同时避免摘要丢证据与生成成本。对本项目的对照基准而言这是学术上最接近的同构物之一——都是"确定性组织 + 原始证据回取"，只是它用**三类机械锚点（时间、共现、情节）**代替人工确认的一跳边，并把关系层的复杂度压到"锚键 → 超边"，完全不需要图数据库。

- 作者·机构: Ruicheng Zhang, Xinyi Li, Tianyi Xu, Shuhao Zhang, Xiaofei Liao, Hai Jin（Cluster and Grid Computing Lab, School of Computer Science and Technology, Huazhong University of Science and Technology）
- 出处: arXiv:2602.13967 (v1) · cs.AI · 未标注会议
- 日期: 2026-02-15（仅 v1）
- 链接: https://arxiv.org/abs/2602.13967
- 访问情况: 2026-09-28 **读到全文 HTML**（正文 51KB 文本，已通读摘要、第 1 节引言、第 2 节相关工作、第 3 节设计与问题形式化（五维 D1–D5）、第 4 节方法开头）；**第 5 节实验分析（含所有结果表与延迟曲线）未读到**
- 方法: 指出现有外部记忆模块评测大多假设**静态**设定（离线建库、固定状态查询），而实际是**流式**：新事实持续到达、插入与检索交错、状态在服务查询的同时演进。据此提出在"插入-检索交错"协议下评测的测试床 Neuromem，把外部记忆模块的形式化写成四个算子（PreIns 归一化、PostIns 按维护策略更新状态、PreRet 由查询构造检索信号、PostRet 取回并精炼出最终上下文）并由底层结构 M 锚定，再映射为五个正交设计维度：**D1 记忆数据结构**（Topology：分区式=离散独立块如扁平向量库，追求快速相似检索；层次式=显式建模实体间依赖如知识图，支持多跳）——它决定状态更新的开销与后续检索的物理效率；**D2 归一化**（PreIns）：把非结构化历史转成离散可存单元，决定摄入信息的粒度与保真度；**D3 整合策略**（PostIns）：冲突消解、容量控制的衰减淘汰、层次记忆的结构精炼；**D4 查询构造**（PreRet）与 **D5 上下文集成**（PostRet，重排或融合）。在共享服务栈内替换各维度的代表变体做受控消融，用 LoCoMo、LongMemEval、MemoryAgentBench 三个数据集，报告 token 级 F1 与插入/检索延迟。作者批评既有评测"粒度粗、效率报告口径不足（平均读写时间掩盖开销位置，缺少内存占用等系统指标与模块开销/模型推理开销的归因）、且多为静态或准静态"。
- 结果: 作者总结为"**复杂度的守恒**"：系统通常在插入与检索之间**转移**计算债而非消除它。关键结论：**混合型数据结构（D1）设定可达的准确率天花板**；**性能通常随记忆在轮次间累积而退化**；**时间相关查询始终是最难的一类**；激进的压缩与生成式整合机制主要是把成本在插入与检索之间搬移，**准确率收益有限**；摘要/摘要式与多查询融合等昂贵操作常常是"延迟陷阱"（latency traps）而收益可忽略。
- 意义: 这是本账本中唯一直接针对 S8（规模与成本）的实证工作，也是对本项目最相关的一条警告：**"记忆越多、精度越低"是被观察到的常态，而时间相关查询最先坏掉**。它同时给出一个可操作的因果定位——退化主要由数据结构（D1）决定上限，而不是由压缩或更花哨的整合机制决定；昂贵操作（摘wa、多查询融合）往往只搬移成本。这为本项目"保持记忆单元数量很小"的选择提供了一个正面理由：在数据结构的准确率天花板之外，累积本身就带来退化，因此**控制规模不是省事，而是控制精度衰减的手段**。
- 疑点·局限: 我**未读到第 5 节**，故"退化"的幅度、随轮次的曲线形状、各维度变体的具体得分与延迟全部来自摘要/引言/设计章节，**未经表格核实**；评测是同一共享栈内的代表性变体（作者自述不覆盖全部现有系统），因此结论是关于"设计维度"而非"产品排名"；三个数据集均为对话/QA 类，与安全日志场景不同；单篇预印本，未见第三方复现。
